Why both

Steps are a flow (what runs, in what order, who runs it): a graph fits. One prompt is a page: sections fit. The industry splits the same way (pipeline builders for flows, ordered context for one call).

A scene without a promptbook has one step and only ever sees option A.

Callouts
  1. 1 The Board shows the turn's steps (the promptbook phases already wireframed in promptbook-board.html). An agent sits in a step's "run by" seat.
  2. 2 Opening a step shows option A's sections for that step's prompt. One way to lay out a prompt everywhere; nodes only for the flow.

Context engineeringThe field moved from "write a good prompt" to "decide what the model sees each call": assembled fresh every call, ordered, trimmed, and visible afterwards. Less is more: stuffing the window makes answers worse. Every option keeps one cost bar and the Inspector.
Progressive disclosure (Agent Skills)Skills load in tiers: names and one-liners always, the body when it applies, extra files only when opened. Our "picked" skills already work this way; all options keep it.
Roleplay frontendsSillyTavern and RisuAI use an ordered prompt list plus lore positions; NovelAI adds per-entry insertion order, reserved tokens and trim direction (the richest budget controls). Option A keeps their mapping and NovelAI's "can it be cut" idea.
Node buildersLangflow and Flowise use canvases for pipelines (model, memory, tools, steps), not for ordering one prompt. That is why option D puts nodes on steps and sections on the page.
