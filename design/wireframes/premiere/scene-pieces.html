4. Time budgets Settings, Scenes
Tools, per reply

How long the narrator's tools may run in one reply. When it runs out, slow tools are told to stop and the reply goes on; tracker updates always land.

5 s
Building the prompt

How long macros may take while a request is built. A macro that runs out is left out and named under the reply; the rest is sent.

3 s
  1. Fields draw by type. A number with a top is a bar (its own To, or another field named as its top, like HP out of Max HP: one new setting on a number field). Choices are pips with the picked one lit, yes or no is one pip, a list is item tiles with a count. Each field and list picks an icon in the tracker editor. Library trackers carry a Library mark and the deck color; built-in ones keep their own panels.
  2. Tools are tiles with an icon for what they do (dice, table, formula, note), their cost in tokens, and a switch. A cost bar sums them per reply; there is no count limit.
  3. Four ways to show what a reply changed, on the same reply. Pick one, or keep D (each tracker chooses) with a scene-wide on and off. Swiping to another version shows that version's changes.
  4. The setting: on or off, and a style. If you pick D, "Each tracker's own" becomes the default and the tracker editor gains its "Show changes on replies as" control.
  5. The out-of-time line appears only when a macro ran out while the prompt was built, names it, and links to the Prompt Inspector where the error already shows.
